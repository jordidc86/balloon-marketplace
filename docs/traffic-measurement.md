# Traffic and contact measurement

The administrator panel is `/admin/traffic`. Collection starts with the traffic release; it cannot reconstruct earlier public page views. Netlify site readback on 3 November 2026 returned `analytics_instance_id: null`; no paid analytics product was enabled.

Public page navigation is collected by a small first-party client. The intake requires the canonical same-origin request and rejects private paths, oversized payloads and common bots. Signed-in admins, webdriver sessions, DNT and GPC are excluded. No IP, full URL query, search text or raw referrer URL is stored. The existing visitor identifier is HMACed with the same UTC daily journey key as commercial actions. Browsers and logged-in accounts are estimates, not identities. Reloads inside ten seconds are coalesced; UUID event keys prevent duplicate deliveries and an atomic 200-event daily journey cap bounds noisy clients. This is not a bot-proof visitor census.

The report has daily visitors and page views, first source/campaign per visitor-day, top pages, total stored marketplace/quote/wanted requests and visitors with an attributable request after their first measured visit. Totals include unattributed requests; conversion only compares joined daily journeys. Repeat days are explicitly visitor-days, never claimed as monthly unique people. Data failures are shown as unavailable, not zero. Raw traffic older than 30 complete UTC days is purged on subsequent intake, only after closed-day anonymous summaries have been archived. There is no new scheduler.

Scheduled social destinations and newsletter listing links already use UTM labels. The newsletter now also has an attributed catalogue button. The panel supplies channel-specific search-launch links. Instagram captions and image-only API stories are not clickable placements; use an actual bio link or a manually added story link sticker. Never infer clicks from a Meta acceptance receipt or an email delivery.

## Monthly history (15 November 2026)

`web_traffic_daily_history` preserves closed UTC-day aggregates (views, visitor-days, converted visitor-days, total requests, raw source/campaign counts and page counts). It contains no journey identifiers or contact details. `/admin/traffic` groups these into calendar months and displays channel conversion rates. Today is computed live and labelled provisional; the first month is partial from the measurement start. No pre-measurement traffic is invented. Daily visitor estimates cannot be summed into monthly unique people.

The service-only archive runs before retention on intake and when the administrator opens history. It fills every missing closed day, including zero-visit days, and never overwrites closed snapshots from a later, truncated raw window. If there is no traffic, raw rows remain until the next intake/read, so no scheduler is needed. Closed snapshots reflect requests stored at archival time; historical backdated imports/deletions require a deliberate reconciliation, not an automatic rewrite. The existing 30-day report remains compatible. Original source labels are preserved; known host/UTM aliases are grouped only for presentation. Ambiguous `fac` and random labels remain Other / unrecognised, not invented Facebook referrals. Direct / unknown is not proof of a typed address.

Conversion measures a stored listing enquiry, quote or wanted request after a measured visit on the same UTC journey-day. Phone/WhatsApp clicks, external contacts, spam filtering and contact reveals are not confirmed conversations. Total requests include unattributed requests and may include spam. The panel makes no claim that these are qualified sales leads.

Migration `20261115110000` is additive except backward-compatible function replacements. RLS and RPC grants remain service-only. Rollback the app without dropping the archive. Rehearsal: `node scripts/rehearse-traffic-history.mjs <path-to-pglite-package.json>` using an isolated PGlite database, plus Node channel/month aggregation tests, lint, types and build. The rehearsal checks expiry preservation, multi-request deduplication, missing attribution, retries, current-day handling and anonymous/authenticated denial.

## Direct contact intent (15 November 2026)

Listing email, telephone and WhatsApp links report a separate contact-click event through `/api/traffic`, using keepalive and never delaying navigation. WhatsApp is offered only for a syntactically valid international telephone number; this does not assert that the seller has a WhatsApp account. Share-to-WhatsApp is deliberately not a seller-contact click. Mobile contact details wrap, fields have accessible names/autofill and appropriate keyboards, and failed enquiry submissions preserve the text and release the button. Seller notifications set Reply-To to the buyer's validated email.

Migration `20261115120000` adds private, RLS-protected click storage and a measurement start timestamp. Only active, accessible listing contact channels are eligible; admins and owners are excluded, DNT/GPC respected, UUIDs and channels validated. The daily journey/listing/channel primary key deduplicates repeated taps, and a 100-row journey cap bounds ingestion. No destination email, phone or message is stored in click events. Sources use a matching first page visit; unmatched clicks are explicitly unattributed. Channel clicks and visitor-days clicking remain separate from stored enquiries and never enter the enquiry conversion rate. Historical days without click measurement remain unavailable rather than retroactively zero.

Closed-day snapshots include click totals before raw expiry. Monthly click-channel totals and daily deduplicated click visitors survive retention. As with traffic snapshots, these are visitor-days, not monthly unique people. Tests: `node scripts/rehearse-contact-clicks.mjs <path-to-pglite-package.json>` and `tests/contact-clicks.test.mjs`. No test enquiries should be sent to real sellers during release verification.
